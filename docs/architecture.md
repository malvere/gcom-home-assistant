# Архитектура

Домен интеграции: `gcom`. Единственная конфигурационная запись представляет аккаунт 10G.com. Все файлы, необходимые для выполнения, находятся в `custom_components/gcom/`.

## Жизненный цикл

Config flow принимает URL и реквизиты клиента, проверяет обновление сессии и сохраняет последний refresh token. Клиент использует общую `aiohttp` session HA для чтения. `EntryTokenStore` обновляет запись при ротации refresh token; access token не сохраняется. Повторная авторизация меняет refresh token через интерфейс.

Coordinator последовательно читает устройства, входы и помещения. Он не опрашивает коды доступа. Сбой обновления делает кнопки недоступными; ошибка авторизации запускает обработку reauth HA. При отключении выгружаются платформы и обработчики. Общая HTTP session HA остаётся под управлением HA.

## Открытие

Для каждого входа из ответа API создаётся `button` с уникальным ID, привязанным к записи конфигурации и ID входа. Это происходит и при выключенном параметре открытия: кнопка тогда недоступна. На каждом обновлении coordinator добавляются новые входы и обновляются названия существующих входов и зданий. Исчезнувшие входы становятся недоступными; при возвращении ID сущности сохраняется. Пользовательские названия сущности и устройства в HA не перезаписываются. Перед командой проверяются параметр открытия, успешность последнего опроса и наличие входа в текущем списке; клиент дополнительно проверяет принадлежность входа аккаунту. Используется только `open_entrance(entrance_id, confirmed=True)` — GET, который имеет физический эффект. POST открытия по `device_id` не представлен в UI.

Команды выполняются без повторов и переходов по редиректам. Изолированная одноразовая session клиента предотвращает повтор mutating GET внутри aiohttp. Этот транспорт пока не наследует пользовательские настройки HTTP session HA. Возврат успеха отражает подтверждение API, а не положение двери.

## Коды

Администраторская карточка использует WebSocket-команды:

| Команда | Назначение |
|---|---|
| `gcom/entries` | Список загруженных записей без секретов |
| `gcom/facilities` | Помещения выбранной записи |
| `gcom/access_codes/list` | Коды собственного помещения |
| `gcom/access_codes/create` | Создание с aware временем окончания и `confirmed: true` |

Сервер проверяет администратора, домен и доступность записи, параметр включения панели, принадлежность помещения через клиент. Сырые ответы API и значения кодов не журналируются. Коды не попадают в coordinator, entity state, recorder, события, сервисы или диагностику.

JavaScript карточки — публичный статический ресурс без реквизитов. Секретные данные поступают только через авторизованное соединение в память карточки. Копирование возможно только после явного раскрытия кода и нажатия кнопки; используется браузерный Clipboard API. После смены контекста или отключения карточки запоздавшие ответы отбрасываются. Очистка карточки не очищает системный буфер обмена. Создание требует подтверждения; неизвестный результат не вызывает повторного запроса.

## Встроенный клиент

`_vendor/gcom_client` — снимок самостоятельного проекта `gcom-client`. Внутри сохранена лицензия MIT и манифест SHA-256. Версия исходного дистрибутива — `gcom-ha-client` 0.1.0. Внешняя публикация в PyPI для установки интеграции не требуется.
