Тесты используют вымышленные данные. Проверены реальные механизмы HA для config flow, хранения обновлённого refresh token, повторной авторизации, обнаружения новых входов и выгрузки. Сценарий с входами «Подъезд №1» и «Двор» проверяет автоматическое создание сущностей даже при отключённом открытии, названия из API, появление нового входа, переименование входа и здания, исчезновение и возвращение входа с прежним ID. Проверено открытие через `button.press`, а также отсутствие команды для отключённого или недоступного входа. Отдельные проверки охватывают opt-in, права администратора, отсутствие секретов в диагностике, неверное время окончания и неопределённый результат команды.

В восьми дополнительных локальных DOM-сценариях карточки подтверждено: запоздавший ответ не возвращает секрет после смены помещения или отключения карточки; одновременные нажатия создания отправляют один запрос; чтение блокируется во время создания; полученный код скрыт до раскрытия. Копирование разрешается после раскрытия и происходит только по явному нажатию, без автоматического копирования при получении или создании кода. Отсутствие Clipboard API обрабатывается сообщением, а завершение устаревшей операции копирования не меняет карточку после смены помещения или отключения.

Проверка схем выполнена официальными валидаторами HA из минимального локального набора скриптов. Полный Hassfest и HACS Action ещё не запускались: они настроены в GitHub Actions и должны быть проверены после публикации репозитория. Живая установка через HACS и взаимодействие с реальным аккаунтом в этой задаче не проверялись. Команды открытия и создания на сервер 10G.com не отправлялись; удалённая dev-верификация не требовалась.
