# 10G.com для Home Assistant

Неофициальная интеграция домофонов 10G.com / Gcom Smart Home. Устанавливается через HACS как пользовательский репозиторий. Поддерживаемая версия Home Assistant — **2026.10.0 или новее**; локальные тесты используют 2026.10.1.

## Возможности

- Получение устройств, групп входов и помещений раз в 5–15 минут.
- Автоматическое создание кнопки для каждого входа из аккаунта, с группировкой по зданию. Новые входы появляются после очередного опроса.
- Карточка просмотра, создания и копирования гостевых кодов для администраторов Home Assistant.
- Сохранение обновлённого refresh token и повторная авторизация через интерфейс HA.
- Английские и русские переводы настроек.

Открытие входов и доступ к кодам по умолчанию отключены. Видеопоток, аудио, звонки и датчик физического положения двери не реализованы. Успешная команда означает подтверждение API, а не проверенное открытие двери.

## Установка через HACS

После публикации этого репозитория на GitHub:

1. Откройте HACS → меню → **Пользовательские репозитории**.
2. Добавьте `https://github.com/malvere/gcom-home-assistant`, тип **Интеграция**.
3. Установите **10G.com** и перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию → 10G.com**.

Интеграция содержит копию Python-клиента. Отдельно устанавливать библиотеку или клонировать соседний проект на сервер HA не требуется. Добавление в основной каталог HACS — отдельный этап; пользовательский репозиторий работает без него.

Для ручной установки скопируйте папку `custom_components/gcom` целиком в `<config>/custom_components/gcom` и перезапустите HA.

## Настройка

Потребуются параметры API вашей существующей сессии Gcom:

| Поле | Что вводить |
|---|---|
| API base URL | HTTPS адрес API с путём `/api/v1/` |
| Token URL | Полный HTTPS адрес OAuth token endpoint, обычно с путём `/auth/realms/SMART/protocol/openid-connect/token` |
| Client ID | Идентификатор клиента приложения |
| Client secret | Секрет клиента приложения |
| Refresh token | Действующий refresh token существующей сессии |

Адреса и секреты не встроены в исходники. Начальный вход по паролю в этой версии отсутствует. Используйте отдельную сессию для HA: одновременное обновление одного refresh token несколькими приложениями может привести к отзыву сессии. Поддерживается один аккаунт на экземпляр HA.

После добавления откройте **Настроить** у интеграции:

- **Включить кнопки открытия входов** — разрешает нажимать обнаруженные кнопки. До включения входы уже видны в HA, но кнопки недоступны. После включения они доступны и автоматизациям; отдельного подтверждения при каждом нажатии нет.
- **Включить панель кодов доступа для администратора** — разрешает чтение и создание кодов через карточку. Создание дополнительно требует подтверждения в карточке.
- **Интервал опроса** — от 5 до 15 минут, по умолчанию 10.

Изменения параметров перезагружают интеграцию. При отзыве refresh token HA предложит повторную авторизацию.

Названия входов берутся из ответа 10G.com: например, «Подъезд №1» и «Двор» станут отдельными кнопками без ручного перечисления. При изменении списка новые входы добавляются после очередного опроса; исчезнувшие становятся недоступными, а вернувшиеся сохраняют прежний ID сущности. Обновлённые названия входов и зданий синхронизируются с HA; ваши собственные названия в HA сохраняются.

## Карточка гостевых кодов

Включите панель кодов в настройках интеграции. Добавьте ресурс панели в **Настройки → Панели → Ресурсы** (может потребоваться расширенный режим профиля):

```yaml
url: /gcom/gcom-access-codes.js
type: module
```

Добавьте на панель ручную карточку:

```yaml
type: custom:gcom-access-codes-card
```

Выберите помещение и нажмите **Load codes**. Значения скрыты до нажатия **Reveal**; после раскрытия кнопка **Copy** копирует выбранный код в буфер обмена. Коды в карточке очищаются через 60 секунд, при смене контекста или удалении карточки со страницы. Уже скопированное значение остаётся в системном буфере обмена. Для создания выберите будущее время окончания и подтвердите действие. Интерфейс карточки пока на английском.

Карточка доступна администраторам; сервер отдельно проверяет права, настройки интеграции и принадлежность помещения аккаунту. Коды передаются только в ответ запрашивающему WebSocket-соединению, не записываются в состояния сущностей, атрибуты, события или диагностику. Карточка не использует localStorage/sessionStorage.

При неопределённом результате команды проверьте вход или обновите список кодов перед новым действием. Автоматические повторы открытия и создания отключены.

## Хранение и ограничения

Client secret и refresh token хранятся в стандартном хранилище конфигурации HA (`.storage`), включая его резервные копии. Это не зашифрованное системное хранилище Keychain; ограничьте доступ к конфигурации и резервным копиям. Access token остаётся в памяти.

API исследован по поведению приложения и может измениться. Ошибки token endpoint, включая сетевые, пока объединены клиентом в ошибку авторизации; временная недоступность этого endpoint может потребовать повторной авторизации. Живые команды в ходе разработки этой интеграции не выполнялись.

## Разработка

Требуется Python 3.14.2 или новее для выбранной тестовой версии HA.

```sh
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-test.txt
python -m pytest
node --check custom_components/gcom/frontend/gcom-access-codes.js
```

Тесты используют вымышленные данные и подменяют клиент; реальный аккаунт не нужен. Клиент отдельно проверяется локальными HTTP-тестами в проекте `gcom-client`.

Обновление встроенного клиента при наличии соседнего проекта:

```sh
python tools/sync_client.py
python tools/sync_client.py --check
```

Скрипт копирует исходники и лицензию, записывает SHA-256 в `VENDOR-SOURCE.json`. При установке через HACS соседний проект не используется. CI проверяет тесты, Python/JavaScript, Hassfest и правила HACS.
